# Product mapping review and confirmation

Select both registered accounts on Products, open **Review** on an Ozon product and inspect the deterministic candidates. Search MoySklad by article, code or exact external identity; products and variants remain distinct and search is paginated. Choose an exact target, including its parent for a variant. Select `OPERATOR_ATTESTED` or, only for an actual candidate, `DETERMINISTIC_CANDIDATE`. Neither is independent verification; an attestation is the local operator's assertion, not evidence of a named individual. No confidence percentage or `INDEPENDENTLY_VERIFIED` option is offered.

Create a durable review. The server selects import revisions and checks registered scopes; the browser cannot set import IDs or session identity. The panel shows the server-returned identities, evidence, revisions, status and expiration. `EXPIRED`, `STALE_SOURCE`, `STALE_MAPPING` and mapping conflicts block new confirmations. Create a new review rather than silently refreshing an old revision. Review creation alone never confirms a mapping.

An explicitly checked acknowledgement and a deliberate confirmation are required. An optional explanation must not include credentials or customer data. Confirmation writes a local mapping and immutable audit through the existing transactional API; it performs no marketplace write. The history displays the version, import references, classification, `LOCAL_OPERATOR_SESSION` principal and explanation when available. Mapping replacement and revocation are unavailable.

The browser generates one cryptographic idempotency key and keeps the exact request in memory. An uncertain outcome, including network loss or `PERSISTENCE_FAILURE`, may have committed: retry the same request. A successful replay remains valid even after review expiration. Switching accounts preserves the original scope and request; return to that scope to retry. Do not refresh or close the tab while an outcome is unknown: memory is lost. After session loss, sign in and inspect the original product's mapping history; another session cannot replay the prior review. No session credentials or keys are stored in browser storage.

The shared local operator secret does not establish individual identity or production tenant authorization. A confirmed mapping does not establish unit equivalence, stock safety or readiness to publish. See [confirmation backend](product-mapping-confirmation-backend.md) for transaction and legacy CLI semantics.

For an isolated browser test, create a fresh local PostgreSQL database named `styk_mapping_ui_e2e_v1`, apply migrations through 18, and run `TEST_DATABASE_URL=... go run ./web/e2e/seed`. Start the Go API on `127.0.0.1:18080` with origin `http://127.0.0.1:15173` and the synthetic secret from `web/e2e/mapping-confirmation.spec.ts`; start Vite on that origin with `/api` proxied to the API, then run `npx playwright test e2e/mapping-confirmation.spec.ts --workers=1` in `web`. The SQL assertion currently uses the local Docker container `styk-live-fixture-test`. The test mutates its synthetic database and needs a fresh database each run. Never point it at production data.
