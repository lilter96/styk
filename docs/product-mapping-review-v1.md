# Product mapping review: read-only slice

Select both registered accounts on the local console's Products page and choose **Review** on an Ozon product. The panel shows the original Ozon identifiers and archive state, deterministic candidate identities and evidence, and whether the candidate list or its source universe was truncated. Search MoySklad by article, code or external identity; results preserve products and variants separately and use bounded pages. Select a result to compare its identifiers with the current suggestion. A matching identifier is a candidate, not proof of identity. Manual selection is an operator attestation, not independent verification. The panel does not assert that source observations are unchanged since review.

The mapping history section reads existing audit entries for the exact tenant, Ozon account, MoySklad account and product. It shows mapping identity, version, provenance, confirmation time and import references. The authenticated GET endpoints `/api/moysklad-products` and `/api/product-mapping-history` require both registered scopes and use bounded pages; `/api/products` provides candidate information. A separate authenticated local API can confirm a durable review; this UI does not invoke it.

Confirmation is deliberately unavailable in the React interface. A separate local API confirms a durable review with source-revision checks, explicit acknowledgement, audit and idempotency. The shared-secret session cannot identify a human or independently verify identity; its principal is a local operator session. A unique candidate and an operator-entered comment must not be promoted to independently verified identity. Replacement and revocation remain out of scope. See [confirmation backend](product-mapping-confirmation-backend.md).

The existing `matching confirm` command remains a trusted local administrative operation: it only accepts a current deterministic candidate, locks its import and matching scopes, and writes the mapping and history atomically. It is not a safe handoff for untrusted users or an independently verified identity mechanism; operators must separately verify account ownership, identity and current imports before using it. No external systems are modified by the review.
