# Stock commitment engine: proposed invariants

Status: design requirements; the read-only slice enforces a subset and deliberately reports unresolved proofs. [Architecture, evidence and examples](stock-commitment-architecture.md); [test matrix](stock-commitment-test-matrix.md). An invariant must be enforced transactionally, by permissions, or by a proved external contract as indicated below; an application comment alone is not an enforcement mechanism.

## Identity, authority and evidence

**I01 — Physical pool identity.** A pool is scoped to an owned MoySklad connection, warehouse UUID, item kind and item ID, with a verified unit. Product and variant, aggregate and warehouse, and Ozon product/offer/SKU are not interchangeable. The same physical pool cannot be independently budgeted under two tenant or account labels. Account ownership must be verified and exclusive by default. A database UNIQUE constraint plus a trusted ownership registry are required; current `source_imports` is only source/account scoped.

**I02 — Tenant/account isolation.** Every evidence, mapping, pool, decision, operation and reconciliation reference must belong to the same authorized tenant and the appropriate owned connections. Composite foreign keys/checks must enforce cross-row scope. Authenticated authorization and database role controls must protect reads and writes; a tenant argument or RLS-free SQL filter is not authentication. Cross-tenant account reuse is blocked unless an explicit shared-pool ownership design coordinates all obligations.

**I03 — Confirmed, frozen mappings.** A decision can use only explicitly confirmed product and warehouse mapping versions bound to the same account pair; suggestions, names and current correlations are not historical facts. V1 requires a one-to-one warehouse binding across account pairs and affirmative proof that an offer consumes exactly one verified source unit, not merely a product match. Preserve original identifiers and mapping versions. Replacement, revocation or conflict invalidates dependent decisions and holds all affected pools until re-evaluated. Existing version-1 mapping tables do not yet implement this lifecycle.

**I04 — Evidence is append-only and independently scoped.** Preserve imported raw values, observation and source timestamps with their basis, import/window identity, completeness, mapping interpretation and provenance. Corrections append new evidence; do not overwrite old observations. Restricted application roles, restrictive FKs and audit must enforce this for new ledger evidence. Existing observation tables have cascading deletes and do not yet enforce immutability against a privileged DB user.

**I05 — No invented event identity or chronology.** Deduplicate a genuine source event only by documented source/account/type/event ID; conflicting content is an error. A content hash can deduplicate delivery/observation processing within its declared scope but is not a source event ID and cannot globally remove `A → B → A`. Import ID, local receipt time, status rank, line ordinal and matching quantities do not establish source update order, line identity or causal reflection. Incomparable source states remain unknown.

**I06 — No implicit zero or completion.** Missing row, missing field, NULL, empty page, restricted permissions, unknown timestamp, unassigned reserve, and an incomplete traversal never mean zero, no obligation, cancellation or deletion. A stored `0` is usable only as a reported value and only with the other evidence gates. Completed pagination and atomic local persistence do not prove a source snapshot or exhaustive coverage.

## Commitments and calculation

**I07 — A source baseline is eligible only with proof.** `P` and `R` must refer to the same pool, compatible source cut and unit; reserve coverage must include or conservatively allocate any warehouse-unassigned reserve and relevant other-channel obligations. Known permissions, non-instantaneous recalculation, page drift and a complete negative-change bound must be addressed. Freshness TTL and recent local read time are necessary policy checks where configured, not proof of current truth. Unsupported negative/fractional values, precision loss, mixed units or unavailable bounds block readiness.

**I08 — An obligation reduces capacity exactly once within the model.** Each quantity is either proven represented by the selected `P`/`R` baseline, or proven unreflected and included once in `U`; unknown overlap makes the output unknown. A physical shipment already represented in `P` is not also subtracted as a reserve. Ozon aggregate `reserved`, posting lines and source reserve are not automatically independent. Splits, partial reflection and related lines need quantified, non-overlapping provenance. Aggregate attribution cannot exceed the proven obligation or the specifically attributable source amount; enforce these cross-row sums under locks, not an unprotected read/check/write.

**I09 — Cancellation and corrections do not create stock by inference.** Preserve cancellations and changes as observations. A canceled posting does not imply all sibling postings, source reserve, source physical stock, or original order quantity was released. Pending release or incomparable ordering may not raise capacity. A later, independently proven compatible baseline and release can change the projection; append evidence and recalculate. Unknown cancellation data remains unknown.

**I10 — Conservative result and explicit uncertainty.** Only if all evidence, coverage, scope, age, mapping, unit and policy gates hold, compute in exact decimal arithmetic `C = max(0, P − R − U − S − D)` using nonnegative `S` and a justified disjoint bound `D`. `D` bounds other possible reductions in the declared risk interval and must not conceal an unproven source overlap. Incoming is excluded. Conversion to channel units must be documented, exact or downward-safe; otherwise block. A decision is `READY_CONDITIONAL` only with a quantity and as-of/bound; `UNKNOWN` and `BLOCKED` have NULL quantity and reasons. No automatic command or numerical zero follows from an unknown result.

**I11 — Every sellable exposure belongs to one pool budget.** A future allocator must ensure, atomically for a common evidenced baseline, `Σ upper-bound active channel exposures ≤ C`. Include pending/unknown writes and other uncontrolled exposures; do not give the full capacity independently to two targets. Local serialization does not control external stock updates or unobserved orders. V1 blocks shared pools, multiple offers, bundles, kit components, competing channels and uncontrolled external writers. Even in a nominally single-target pool, prove exclusive resource/control and bound unseen decrements or return unknown.

**I12 — Determinism does not manufacture certainty.** Given the same evidence set, applicable trusted ordering, scope and policy version, rebuilding yields the same decision and ordered explanation. Repeated delivery is idempotent for projections while append-only observations can repeat. Reordering incomparable inputs must not choose a winner; conflicting states remain unknown. Permutations with a valid source sequence may be replayed in that order. A previously returned decision retains its original evidence and meaning.

**I13 — Decisions are perishable.** Store all evidence and mapping versions, baseline, as-of interval, policy, uncertainty bound and expiry. Validate their revisions and remaining risk window under the pool lock at use time. New evidence, policy/mapping changes, failed reads, expired freshness or unresolved in-flight operations invalidate the relevant decision. A later ID, last completed batch or recent insertion is not by itself a new business-state timestamp. No guarantee of continued safety follows solely from a TTL.

## Future external publication and recovery

**I14 — Four external facts remain distinct.** Desired, attempted, acknowledged and independently verified state are separate records with separate time, scope and outcome. A per-item HTTP acknowledgment may establish acceptance, not external convergence. Stock readback can be stale, missing or expressed in different units/semantics. Never infer an external effect from a local outbox state.

**I15 — Ambiguous writes stay unknown.** A timeout, crash after a possible send, ambiguous 5xx, lease expiration, lost response or partial response is not confirmed failure. Preserve upper-bound exposure and block the target lane. Retry only after a verified idempotency/conditional-write contract or evidence-backed reconciliation and quiescence; if an old request could still apply, a single successful read is insufficient. The existing mock `ExpireExhausted` and lease recovery do not satisfy this invariant.

**I16 — Serialize the local decision, not the network.** Before any future external write, transactionally validate the pool revision, frozen mapping/policy and freshness; lock pool and target lane; persist unique intent plus outbox entry and commit. No network call occurs within a transaction. Local unique keys and claim tokens fence database writes, not already in-flight external requests. For strict external ordering require a documented external conditional version or a safe quiescence/reconciliation protocol; otherwise remain blocked. Concurrent attempts and crash recovery must never create two simultaneously eligible local intents for a target.

**I17 — Failure cannot erase evidence or disable an existing offer.** Failed reads and rolled-back DB transactions leave earlier evidence and decisions available for audit but do not make them fresh. Read-only `UNKNOWN`/`BLOCKED` prevents new publication, yet existing Ozon listings may remain sellable. Record and alert on that exposure; mitigation requires a separately authorized operational procedure. No automatic real-world change is implied by a read-only hold.

**I18 — Reconciliation is evidence, not a magic retry.** Independently observed target values must be interpreted using verified API semantics, account/warehouse/product scope and observation time. Record disagreements and partial success. Convergence can close an unknown outcome only if no older request can later invalidate it and the required ordering/settling assumptions are proven. Manual intervention is an auditable uncertainty resolution, not silent conversion to success.

## Minimum merge and write-enablement gates

Read-only V1 must have deterministic unit/property tests and database tests covering I01–I13 and I17, with all unsupported real inputs returning explicit unknown/blocked explanations. Any future writer additionally requires I14–I18, documented current Ozon semantics, tenant authorization, operational monitoring, a tested account with synthetic data and explicit approval. All gates in the [architecture](stock-commitment-architecture.md#scope-phases-and-go-no-go) are necessary; none assert exactly-once external effects or eliminate uncontrolled marketplace risk.
