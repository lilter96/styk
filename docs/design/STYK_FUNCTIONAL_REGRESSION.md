# Проверка регрессии

## Выполнено

- `npm run build` — успешно; TypeScript и production-сборка прошли. Начальный JS: 437,32 КБ, gzip 127,03 КБ. Каталог: 61,36 КБ; интеграции: 66,99 КБ. Предупреждения о чанке более 500 КБ нет.
- `npm test` — 18 файлов и 200 тестов прошли. В том числе существующие тесты авторизации, интеграций, импорта, сопоставления, каталога и управления остатками, а также новые проверки уже подтверждённой пары складов и контекстной подсказки в обзоре.
- `npm run lint` — успешно.
- Playwright: 10 проверок прошли. Все шесть рабочих маршрутов проверены на 1920×1080, 1440×900, 1366×768, 1280×800, 768×1024 и 390×844; проверены отсутствие горизонтального переполнения и ошибок JavaScript, мобильное меню, Escape, удержание и возврат фокуса, merchant-формы входа/регистрации/восстановления/повторного подтверждения, поиск, пагинация, выбор разных аккаунтов одного провайдера, окно подключения на desktop и mobile.
- Визуальные проверки используют настоящие компоненты приложения и изолированные ответы API исключительно внутри теста. Это не изменение production API и не замена рабочего приложения демо. Скриншоты создаются в `web/test-results/redesign`.
- Те же 9 проверок представления дополнительно прошли на production build через Vite preview (`4173`), включая загрузку отдельных JS/CSS-чанков. Репрезентативные скриншоты сохранены в `docs/design/screenshots`.
- Отдельный Playwright-тест прошёл с настоящим Go API, PostgreSQL и обычным merchant-входом по почте и паролю. Проверены авторизация и переходы по всем шести маршрутам без ошибок JavaScript. Использовалась отдельная локальная БД `styk_ui_redesign` с существующим синтетическим seed `cmd/doctor -demo`.
- До переключения preview на merchant прошёл существующий `npm run test:browser` (smoke): local-вход, выбор контекста, реальные запросы, товары, склады/остатки, диагностика.
- Через официальный Docker-образ Go 1.27.3 прошли `go test -race ./...`, `make test`, `make build`, `go build ./...`; `golangci-lint` v2.15.0 сообщил `0 issues`.
- На визуальной проверке исправлены лишняя кнопка меню на desktop, перенос шапки на mobile, переполнение старого контейнера при 1280 px, плотность мобильных строк и контраст текста основных кнопок.

## Ограничения и проверки, которые не следует считать пройденными

- Полная проверка всех редких состояний, каждого существующего e2e-файла и реальных внешних провайдеров не выполнялась. Тесты с fixture-ответами проверяют представление и отправку существующих параметров, но не доказывают корректность внешних интеграций.
- Проверка скорости больших списков, утечек памяти и полного набора требований доступности.
- `make lint` останавливается на первом этапе gofmt: существующие Go-файлы в Windows checkout имеют CRLF. Прямой запуск golangci-lint прошёл; форматирование backend ради frontend-задачи не менялось.
- Полный `go test -tags=integration -count=1 ./tests/integration/...` выполнен в отдельной локальной БД `styk_ui_regression_test`: остаются 7 ошибок `TestStockImportedEvidenceIsUnknownAndImmutable`, `TestStockPolicyVersionsAreImmutable`, `TestStockMissingMappingVersionIsBlocked`, `TestStockRepeatedImportAndMissingObservation`, `TestStockConflictsAndMappingVersionHistory`, `TestStockDecisionRollbackAndConstraint`, `TestStockMappingChangeDuringCalculation`. Все 7 отдельно воспроизведены на исходном `master` из `git archive` в той же среде. Это базовые ошибки набора backend-тестов в данной среде, не новая регрессия frontend. Backend не исправлялся в рамках визуальной задачи.
- В preview настроен вход существующей локальной тестовой учётной записи. Позднее по запросу пользователя запущен локальный Mailpit на loopback `8025`/`1025` с существующим доверенным TLS-сертификатом: доставка письма восстановления для локальной preview-учётной записи подтверждена. Новый пароль пользователь задаёт самостоятельно; прохождение сброса целиком не заявляется. Внешние токены провайдеров не заданы, worker не запускался, внешние публикации не выполнялись.

Состояние пары складов preview проверено настоящим API: `ALREADY_MAPPED`, `WAREHOUSE_MAPPINGS=PASS`, одно подтверждённое соответствие. Повторная запись не создавалась. Playwright с настоящим merchant API подтвердил новый текст обзора, просмотр этой пары, отсутствие предложения повторной проверки и закрытие кнопкой «Готово». Сборка и lint прошли.

Для повторного запуска: `npm test`, `npm run lint`, `npm run build`; затем при работающем Vite — `npx playwright test e2e/redesign.spec.ts --workers=1`. Live merchant-тест включается переменными `STYK_UI_MERCHANT_EMAIL`, `STYK_UI_MERCHANT_PASSWORD` и необязательной `STYK_UI_MERCHANT_ORIGIN`; тестовых паролей в исходниках приложения нет.
