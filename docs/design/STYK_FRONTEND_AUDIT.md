# Аудит frontend STYK

Базовое состояние: `master`, рабочее дерево чистое; создана ветка `feature/styk-full-ui-redesign`. Реальный интерфейс — `web/`, визуальные источники — соседние `styk-landing` и `styk-demo`. Демо использует примерные данные и не определяет наличие функций в рабочем приложении.

## Архитектура

React 19, TypeScript, Vite, React Router и TanStack Query. Стили: `style.css`, `imports.css`, `mapping.css`, `catalog-sync.css`. API и типы находятся в `api.ts`; данные загружаются с `/api/*`. Состояние форм и выбранных аккаунтов хранится в React, запросы — в React Query; выбранный контекст сохраняется в sessionStorage. Авторизация поддерживает локальный ключ и merchant-сессию; CSRF и защищённые запросы реализованы в `api.ts`. Права и ограничения операций проверяются сервером. Компоненты подтверждения и отправки сохраняют состояние неоднозначных результатов и исходный контекст.

## Компоненты и сохранение логики

`App.tsx` отвечает за маршруты, контекст, сессию и глобальные уведомления. `MerchantAuth`, `Integrations`, `IntegrationDialog`, `CredentialEditor`, `ImportPanel`, `ProductMappingPage`, `ProductReview`, `WarehouseReview`, `CatalogSync*`, `StockSyncControls`, `AutomaticStockControls`, `StockShadow`, `OrderEvidence` и `Confirmation` реализуют рабочие сценарии. Их запросы, обработчики, валидация, состояния, разрешения и подтверждения следует сохранять при оформлении.

## Визуальные источники

Демо использует Inter, фон `#f6f8ff`, текст `#111936`, основной `#693cff`, голубой `#1769ff`, градиент `#693cff → #9254ff`, белые поверхности с тонкой рамкой и радиусы 8–15 px. Лендинг использует близкую палитру `#7847ff`, `#10183e`, `#f8f9ff` и умеренные тени. 3D в демо служит декоративным приветствием; в рабочих формах и списках оно не требуется.

После реализации все шесть рабочих маршрутов используют `AppShell`; формы авторизации сохраняют отдельный брендовый layout. Источники данных, hooks, API-клиент и компоненты подтверждения не переписаны. Каталог и интеграции выделены в lazy chunks. Подробности реализации и доступной проверки находятся в соседних документах дизайн-системы, changelog и регрессии.
