# Durable product mapping reviews

The local authenticated operator API can create and inspect an immutable review of one Ozon product and one exact MoySklad product or variant. `POST /api/product-mapping-reviews` accepts JSON fields `tenant`, `ozon_account`, `moysklad_account`, `product_id`, `target_kind`, `target_id` and `evidence_class`. It requires the configured loopback Origin and an active operator session. The server resolves both latest eligible completed imports and rejects missing registrations, missing identities, unsupported evidence and invalid requests. It returns a random review ID, import references, existing mapping version if present, conflict flag and status. Import IDs, session audit identifiers and principal types are never accepted from the request.

`DETERMINISTIC_CANDIDATE` requires that the existing matching engine finds the exact selected item by the imported identifier evidence. `OPERATOR_ATTESTED` permits a manual selection with differing identifiers. Neither proves product identity. `INDEPENDENTLY_VERIFIED` is represented in the domain but rejected because there is no verification provider. A review is not an approval and does not create a mapping, mapping history or publication task.

`GET /api/product-mapping-reviews/{id}` requires the same active local operator session that created the review. The server revalidates registered scopes, selected identities, eligible import IDs and mapping state. It returns `CURRENT`, `EXPIRED`, `STALE_SOURCE` or `STALE_MAPPING`. A newer completed import makes a review stale even when selected values match; identical deduplicated imports keep their original ID. The server also hashes the selected stored source fields and mapping state to detect in-place changes. A privileged database actor can alter existing source data outside the application's locking protocol; these hashes detect differences still present at inspection, but cannot reveal a change that was later reverted and do not turn old source rows into immutable snapshots.

`STYK_REVIEW_LIFETIME` defaults to 5 minutes and must be positive and at most 10 minutes. Stored review rows and their original revision references are immutable; stale reviews are never refreshed. Reviews and their source/account references use restrictive foreign keys. The migration refuses rollback while reviews exist.

The application takes transaction-scoped advisory locks in the established order `ozon:<account>`, `moysklad:<account>`, `matching:<tenant>`, shared with the importers and legacy mapping confirmation. No external request is made while holding these locks. The guarantee covers cooperating application paths; imported traversals are not atomic external snapshots. If a mapping already conflicts with the selected identity, the result reports the conflict rather than silently replacing it.

Each successful login creates a separate cryptographically random session audit identifier, distinct from the cookie credential and operator secret. It is stored with the review under principal type `LOCAL_OPERATOR_SESSION` and is stable for that session. Sessions are in memory; after restart or expiration a new session cannot inspect the old session's review. The shared local secret does not identify an individual human or provide production tenant authorization.

No mapping-confirmation endpoint, idempotency mechanism or React confirmation is implemented. A future confirmation transaction must revalidate the review, source revisions, identity and mapping conflicts under the same locks; persist mapping and immutable audit atomically; and bind retries to a scoped idempotency key. Operator attestation must never be presented as independent verification or as proof of stock safety. Stock decisions continue to be restricted to UNKNOWN or BLOCKED; no publication is enabled.
