# Web console: local imported-data validation

On 2026-10-29 the console was exercised against the existing disposable loopback PostgreSQL cross-system test database, containing the previously authorized read-only imports. Both registered account scopes were selected. Migration 16 was applied locally for the console's stock indexes. No API calls to either external system were made during this validation; completed traversals are not point-in-time snapshots or proof of current connectivity.

The browser used the real Go API and authenticated local session. API responses accessed by the browser reported 9 MoySklad products, 2 variants, 3 warehouses and 33 warehouse-stock rows; 33 Ozon products, including 24 archived and 5 missing SKUs; 13 Ozon warehouses, 7 FBS and 6 rFBS; and 5 Ozon stock rows. A separate local database query confirmed all five explicitly report zero. The browser opened a warehouse with zero stock and another with no stock observation, verifying that the two are presented differently. No row is interpreted as zero. Both product and warehouse mapping counts were zero; the matching endpoint returned no candidates for the 33 products. Current counts are observations from this database, not fixed expectations for future imports.

Overview, Products, Warehouses and Diagnostics were opened in Chromium; scoped API counts, archived and missing SKU fields, warehouse classification and diagnostic status were checked. Diagnostics returned NOT_CHECKED for stock calculation and DISABLED for publication. The traversal fits on one product page at the current limit of 50; multiple-page behavior is covered by synthetic PostgreSQL tests rather than by this dataset. Browser screenshots were captured locally with account selectors, tenant header, product rows and warehouse rows masked; they are ignored by Git. The browser verification does not establish real-world product or warehouse identity, current API connectivity, complete stock coverage or safe publication.

The overview now shows the source's local import timestamp and links to product, warehouse/stock and diagnostic review. Product and warehouse views reset their pagination and selection when the account scope changes. The previous future-time warning was caused by the synthetic Doctor fixture's fixed UTC timestamp relative to the local test clock. The warning remains: the Doctor computes age from the UTC instant, and a negative duration means the recorded observation is in the future; rendering uses the browser's local timezone. This is not a source-event time.

Synthetic frontend tests and the existing integration suite were run without marketplace credentials. The local operator session remains a trusted single-machine boundary, not production authentication. Product confirmation, warehouse mapping, order synchronization and stock publication remain unavailable.

Local redacted screenshots are kept under `.local/web-validation/` and excluded from Git. They mask tenant/account selectors, product rows and warehouse rows. Synthetic regression tests additionally cover the future-timestamp warning, account switching and existing pagination, authentication and unknown-stock behavior.
