# Покрытие нативных отгрузок: LIVE-проверка 2026-11-07

Первоначальный штатный GET четырёх связанных `customerorder` вернул
`demands` только у одного документа; у трёх поле отсутствовало. Отсутствие поля
сохранено как неизвестное значение. Нулевые `shipped` и `reserve` у строк
заказа сами по себе не доказывают отсутствие сторонней черновой отгрузки.

## Проверенный контракт и исправление

Документация [Отгрузки](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/documents/_demand.md)
описывает связь `customerOrder`, но не объявляет её фильтруемым полем.
В [общем контракте фильтров и прав](https://raw.githubusercontent.com/moysklad/api-remap-1.2-doc/master/md/_general.md)
`customerOrder` отсутствует среди фильтруемых ссылочных полей. Там же
`permissions.<entity>.view=ALL` означает просмотр всех документов; `OWN` и
другие ограниченные области не дают такого покрытия.

Отдельный реальный read-only probe `entity/demand?filter=customerOrder=<URL>`
для каждого из четырёх родителей вернул **HTTP 412, код 1034, customerOrder**.
Этот неподдерживаемый фильтр в приложение не добавлен.

Добавлена отдельная возможность `ReadNativeDemandCoverage`. Штатное чтение
`ReadCustomerOrder` сохраняет прежние поля, JSON, raw revision и стоимость
запросов. Только автоматический `DemandCreate` с отсутствующим либо `null`
`demands` запрашивает дополнительное покрытие:

1. Свежий `context/employee`: точный `accountId` и явный `permissions.demand.view=ALL`.
2. Полный нефильтрованный обход `entity/demand`, `order=id,asc`, `limit=1000`,
   локальный `offset`. Нет фильтра по дате, проведению, владельцу или родителю.
   Черновики входят в обход. Проверяются явные `size/offset/limit`, все строки
   каждой страницы, уникальные упорядоченные UUID, точный account, native href
   и тип документа. Каждая присутствующая связь `customerOrder` проверяется
   на точный account-bound origin/path/type/UUID. Чужой родитель не присваивается.
3. Второй полный обход должен вернуть тот же упорядоченный набор ID → parent.
4. Повторный `context/employee` должен всё ещё подтверждать `demand.view=ALL`.
5. Полный повторный GET родителя со всеми позициями должен иметь прежний raw revision.

Доказательство хранится отдельно в команде: scope, correlation, parent revision,
число просмотренных документов, точные найденные demand IDs, интервал чтения,
`ALL` и `complete`. Никакие синтетические `demands=[]` в provider JSON не
вставляются. Отсутствующий новый указатель исключён из JSON старых команд;
исторические fingerprints и UNKNOWN readback не переопределяются.

Явная непустая связь из header сохраняет блокировку независимо от обхода.
Любая найденная связанная отгрузка, включая `applicable=false`, требует review;
она не принимается за собственную по имени или нулевым счётчикам. Перед новым
POST native preflight заново проверяет покрытие. Ошибка страницы/прав, неполный
ответ, изменение набора/родителя и исчерпание бюджета сохраняют неизвестность.

## Проверки и границы

Focused `-race` проверки domain, HTTP adapter и planner прошли; `go vet` этих
трёх пакетов прошёл. Регрессии включают `null`/отсутствие, полный многостраничный
обход, drafts, чужой account/href/parent, дубликаты, неполные и изменившиеся
страницы, отзыв ALL → OWN, изменение родителя, page 403, повторный final guard,
устаревшее доказательство, сохранение старого JSON и часы после сетевого чтения.
Итог полного regression lane фиксируется в общем отчёте запуска.

Используются существующие ограничения штатного native reader: 2 минуты,
128 запросов, 4 MiB на ответ и общий предел коллекции STYK 200000 строк.
Это ограничения ограниченной работы/памяти приложения, не лимиты провайдера;
обход, который в них не завершился, никогда не считается пустым или COMPLETE.
Отдельного искусственного предела 1000 документов аккаунта нет.

Штатный orders worker использует собственную lease **3 минуты**:
`cmd/worker/orders.go` не передаёт `LeaseDuration`, и `defaultRunnerOptions`
задаёт это значение. Общая настройка mock/import worker
`WORKER_LEASE_DURATION=30s` к этому runner не применяется. Продление native
work на лету не добавлено. Измеренные 14–16 секунд дополнительного покрытия
входят в фазу вместе с остальными preflight reads; медленный/большой обход
по-прежнему может закончиться без POST при истечении срока.

Обычный список охватывает активные документы, включая черновики, а не удалённую
историю. Существующие UNKNOWN, удалённый собственный документ и корреляционные
конфликты остаются под отдельными запретами повторной отправки.

Два совпавших обхода и перечитывание родителя не являются транзакционным snapshot
аккаунта. МойСклад не предоставляет здесь условный POST отгрузки по revision
родителя или CAS отсутствия чужой отгрузки. Другой пользователь может создать
документ после последнего GET; тот же `syncId` защищает наш документ, но не
независимый сторонний документ. Поэтому абсолютное отсутствие двойного списания
при конкурентном внешнем writer этим контрактом не гарантируется.
