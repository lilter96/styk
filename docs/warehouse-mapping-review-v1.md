# Warehouse mapping review V1

In the local operator console, select a registered tenant and both accounts, then open Warehouses. Select one MoySklad warehouse and one Ozon warehouse. The review reads the latest eligible completed imports and displays original identities, accounts, import observation times, stock-row counts, Ozon status and FBS/rFBS classification. A missing row or absent import is unknown, not zero. Existing stock details remain source-specific: MoySklad stock, reserve and incoming are separate from Ozon present, reserved and free stock. The view does not compare or calculate them.

The authenticated read-only `GET /api/warehouse-mapping-review` takes `tenant`, `moysklad_account`, `ozon_account`, `moysklad_warehouse`, `ozon_warehouse` and optional bounded `offset`. It reads registration, current imports, mappings and history in a repeatable-read, read-only transaction with the configured query timeout. It returns `ELIGIBLE_FOR_REVIEW`, `ALREADY_MAPPED`, `MAPPING_CONFLICT`, `UNSUPPORTED_WAREHOUSE` or `MISSING_SOURCE_EVIDENCE`. Only explicitly reported FBS (`is_rfbs=false`) is supported. One-to-one constraints apply within the tenant and account pair; names do not establish identity. A mapping outside the registration's historical visibility is not exposed and prevents eligibility. Audit history is paginated, scoped and respects the registration's import-history policy.

Eligibility describes a local observation, not proof that warehouses share physical inventory. The source can change immediately after the request, and completed traversals are not atomic source snapshots. The initial pair inspection is read-only. History shows existing mapping IDs, versions, warehouse identities, provenance and confirmation timestamps; it cannot be edited.

For an eligible pair, create a durable review, inspect its identity, source import references, status and expiration, then explicitly acknowledge the relationship before confirming. A `CURRENT` review is not independent physical-identity evidence. `EXPIRED`, `STALE_SOURCE` and `STALE_MAPPING` require a new review; existing and hidden conflicts cannot be overwritten. Confirmation records `OPERATOR_ATTESTED` with the shared `LOCAL_OPERATOR_SESSION`, not an identified human or independent verification. The confirmed version and scoped history are refreshed. See [backend semantics](warehouse-mapping-reviews-backend.md).

The browser retains the original request and cryptographically generated idempotency key in memory when a response is lost or the outcome is uncertain. Retry the same request in the original session and scope; switching accounts does not cancel a transaction. A successful replay is allowed after review expiration. Closing the page loses the in-memory retry context; session loss prevents replay from a new session. Sign in and inspect scoped mapping history instead. No key or session credential is stored in localStorage.

 Confirmation establishes neither stock ownership nor safe publication; it creates no stock pool, decision or publication task. Aggregation, splitting and allocation are not implemented.
